# Research: SignalSlate repository review (conciseness, completeness, accuracy, redundancy, design)

**Date**: 2026-10-12
**Type**: Architecture Decision (codebase review)
**Status**: Complete
**Stack**: Python 3.12 container (3.13 locally): FastAPI 0.115.0, SQLModel 0.0.22, APScheduler 3.10.4, requests, msal, pytest; web: Nuxt ^3.13, Quasar ^2.17 via nuxt-quasar-ui ^3.1, Vue 3.5, TypeScript ~6.0, Vitest ^5; Docker compose, SQLite

## Summary

The codebase is in good shape where it counts: no layering violations between `pipeline/`, `api/` and `web/` apart from one import, zero `any`/`ts-ignore`/TODO in the web app, every documented env key, command flag, route and page verified against code, and both test suites green (3464 Python tests after pointing Playwright at the installed Chromium, 528 web tests). The debt is copy-paste: the same HTTP `request()`/`ApiError` block in four web composables, the same retry loop in four ATS modules, `_coded()` in eight routers, three identical health checks, four Anthropic structured-output call skeletons, and three settings parsers. Three P1 defects surfaced: `PUT /api/config` persisted an unparseable cron that then crash-looped the container on every restart, and the README documented a dead env key (`MSTODO_ORG_ALIAS`) and an unused Graph scope (`ChannelMessage.Read.All`). The mechanical, test-covered share of the cleanup was applied on this branch (57 files, net about 560 lines removed, token-level duplication 1.36% to 0.47% per jscpd, no new type errors), together with a test-isolation fixture: 26 tests depended on the repository's real `data/digest.db` having tables and failed on a clean checkout; every test now gets its own database. The rest is sized below for `/blitz:plan`. The one strategic item is dependency age: Nuxt 3 left maintenance on 2026-07-31, and python-dotenv 1.0.1 and pytest 8.3.3 carry open advisories.

## Research Questions

### Q1 (redundancy): Where is logic duplicated, and which duplicates are safe to remove now?
**Answer**: Six clusters. (1) Web: `isRecord`/`describeValidationEntry`/`toApiError`/`request`/`seg` copied verbatim into `useDomainsApi.ts`, `useJobsApi.ts`, `usePackagesApi.ts` (71 lines each) plus `isRecord` in two components. (2) ATS: the retry/backoff/Retry-After loop forked into `jsonld.py`, `personio.py`, `workday.py` beside `ats/__init__.py::fetch_json` (about 60 lines each) with the same five constants and `_USER_AGENT` in five files. (3) API: `_coded()` in 8 routers (76 call sites), `_scrub()`/`_MAX_TEXT` in 3, `ImportBody/RejectedRow/ImportOut` in 2, scheduler trigger/reschedule/next-run triplets. (4) Pipeline core: `finish_paste`/`finish_callback` and `_raise_provider_error` across the four oauth modules, M365 silent-token acquisition in `health.py` and `collectors/graph.py`, naive-UTC conversions hand-rolled four ways, `check_domains/jobs/packages` triplicated. (5) Features: the Anthropic `messages.parse` skeleton six times (`ideas.py`, `inbox_seed.py`, `packet.py`, `research.py`, `scoring.py`, `assist/mapping.py`), settings parsing three ways (`domains/__init__.py`, `jobs/__init__.py`, `packages/__init__.py`), registrar `_domain_tld`/`_TIMEOUT`. (6) Tests: web test helpers (`apiFailure`, `stubFetch`, mount tracking) copied across 18 to 21 files. Clusters 1, 2, 3 and the small items in 4 and 5 were mechanical and test-covered and are applied on this branch. The oauth finish flows, the LLM-call helper and the settings helpers change public shapes or test doubles and go to the plan.

### Q2 (completeness): What is incomplete or dead?
**Answer**: No stub code paths in production. Dead or test-only symbols: `oauth_zoom.revoke` (docstring says nothing wires it), `connections._secrets_for`, `gmail._html_to_text`, `db.item_counts_for_run`, `jobs.normalize_city`, `resolve.fingerprint_html`, scheduler `next_{domains,jobs,packages}_run_time` (removed), namecheap `RATE_LIMIT_*` constants (removed). Unwired: `domains/purchase.reconcile_unknown()` is the only path that resolves an "unknown" (possibly charged) purchase and nothing schedules it. Write-only: `RawPosting.posted_at` and `apply_mode` are produced by all 11 adapters and read nowhere; `Run.pdf_path` is never assigned so `GET /api/runs/{id}/pdf` is unreachable and untested. Test isolation (fixed on this branch): `test_dry_run.py`, `test_runner_only.py` and one `test_runner.py` test reached `pipeline.db` through `known_sources()` without patching the engine, so they queried the repository's real `data/digest.db`, which has no tables on a clean checkout; 26 tests failed in every clean full run of the untouched tree (verified with all changes stashed and a plugin that watched the real file: the `connection` table never appeared) and passed only when an unrelated process had created the tables. `api.routers.job_apply` and `pipeline.jobs.packet` also bind `DB_PATH` by name at import and wrote `data/jobs/applications/1/cover_letter.pdf` into the repo during tests. An autouse fixture in `tests/conftest.py` now gives each test a copy of a session-built schema file, its own `config.json`, and rebinds those two modules' `DB_PATH`; the suite runs in the same 197 s and leaves `data/` absent.

### Q3 (accuracy, docs): Do README, CHANGELOG, .env.example and docs/ match the code?
**Answer**: Mostly yes: all 45 `.env.example` keys, their defaults, every README command and flag, the 14 documented routes, the 5 documented pages and all 9 relative links verify. Misleading before this branch: `MSTODO_ORG_ALIAS` is documented but never read (To Do is collected from every tenant), `ChannelMessage.Read.All` is recommended but no collector requests it, the README phase list omitted the built-but-unwired triage stage and the Domains/Jobs/Packages consoles, `pytest` as documented fails without `requirements-assist.txt` (five test files import Playwright), the Namecheap sandbox host is `www.sandbox.namecheap.com`, the landing page says sources are queried "in parallel" (the runner is sequential). All fixed on this branch. Still open: CHANGELOG starts at 1.3.0 while tags v1.0.0 to v1.2.0 exist on the remote; its 14 short SHAs that are not ancestors of `main` do resolve on GitHub (checked with the GitHub API), so the links work.

### Q4 (accuracy, vendor): Are the third-party API and dependency claims still correct as of 2026-10-12?
**Answer**: Verified against official pages: Google 7-day Testing expiry, 100-token cap and six-month idle revocation; Slack internal apps exempt from the 2025-05-29 non-Marketplace rate-limit tiering; Zoom S2S tokens last one hour with no refresh; Namecheap 20 domains / $50 balance / $50 spent and IPv4-only allowlist; GoDaddy issues Personal Access Tokens; Entra accepts custom `https://` redirect URIs. Outdated or imprecise: the Entra "Block device code flow" managed policy ships Report-only and auto-enables after 30 days (README implies always-on); USPS now steers new integrations to Tracking v3.2, not v3.0; Zoom published two new Summaries APIs in August 2026 that the collector does not use. Unconfirmed (official page not reached): Zoom scope names and `/users/{id}/meeting_summaries`, USPS 60 calls/hour, GoDaddy availability tier thresholds, WordPress.com refresh-token behaviour, UPS access-key retirement date. Dependencies: Nuxt 3 is past end of life (2026-07-31); python-dotenv 1.0.1 (GHSA-mf9w-mj56-hr94, fixed 1.2.2; the app never calls `set_key`, so exposure is nil) and pytest 8.3.3 (GHSA-6w46-j5rx-g56g, fixed 9.0.3) have open advisories; FastAPI 0.115.0 is 28 minor releases behind, SQLModel 0.0.22 is 26 behind, msal one minor behind; cryptography and requests pins are above every 2026 fix found.

### Q5 (design): Do module boundaries hold, and which structural changes would pay off?
**Answer**: Boundaries hold: no `pipeline -> api` import except `domains/snapshot.py` importing `iso_z` (moved to `pipeline/clock.py` on this branch), no router reaches private pipeline symbols except three (`inventory._upsert_postings`, `health._raw_env`, `registrars._egress`). Two god modules carry most of the structural debt: `pipeline/health.py` (848 lines: env/overlay settings, M365/Zoom/Gmail/Slack checks, source registry; most-imported module, with import-cycle comments that no longer match the code) and `pipeline/connections.py` (1,150 lines: kinds registry, validation, CRUD, secret envelope, `.env` seeding, overlay). `runner._execute_run` is a 118-line function with the stuck-streak block twice. Routers hold orchestration that the scheduler duplicates (`domains.sync` and `packages.scan/refresh` vs `api/scheduler.py`). Error contract is three shapes (`{code,message}`, plain string, 422 list). `packages/` is the cleanest of the three feature packages (session injected, validated settings) and is the template the other two should converge on. Datetime handling is consistent by convention (naive UTC, `clock.utcnow`); the 118 ruff DTZ hits are that convention, not bugs, except UPS scan times parsed as UTC.

### Q6 (conciseness): Where are code and docs verbose beyond their value?
**Answer**: Comments and docstrings are 36% of the feature packages (4,331 docstring lines of 12,817 LOC by AST count); the ATS adapters repeat the same three "design decision" bullets in 9 of 11 headers and the same `Raises:` sentence 22 times; 31 `T-0xx` task ids and 60 "research doc" references live in code. The README (634 lines) restates `.env.example` for Host/Origin settings three times and for the Packages keys once, and about 60% of it is vendor click-path prose; a 34% cut is possible by moving the Domains/Jobs/Packages sections and vendor setup to `docs/setup/`. `tests/` carries 296 `# noqa: E402` comments that a 3-line `ruff.toml` (`per-file-ignores`) would retire, and the repo has no lint or format config at all, so the 1,480 ruff findings and 210 unformatted files reflect an unmade decision rather than drift.

### Design

- **God modules**: `pipeline/health.py` (848 lines, 42 defs: settings/env overlay at `:96-335`, M365 at `:336-390`, Zoom at `:392-607`, Gmail/Slack at `:610-730`, local checks and `known_sources` at `:732-848`) and `pipeline/connections.py` (1,150 lines; `class ConnectionError` at `:101` shadows the builtin). Both are imported by nearly everything, so the split (`pipeline/settings.py`; `connections/{kinds,validate,store,env_compat}.py`) needs its own plan.
- **Import-cycle workarounds rest on a misplaced constant**: `oauth_gmail.py:32` and `oauth_google.py:22` import `GMAIL_SCOPE` from `health`, which forces lazy imports of `oauth_zoom` inside `health.py:487,590` and a stale cycle comment at `health.py:113`. A leaf `pipeline/scopes.py` removes both.
- **Routers carry orchestration**: `jobs.py:279-334 rescan_company` re-implements resolve/research/poll; `job_apply.py:303-332` writes files; `domains.py:343-350` and `packages.py:280,299` duplicate what `api/scheduler.py:85-86,121-125` runs. One pipeline function per operation, called by both.
- **Error contract**: `{code, message}` (66 sites), plain string (8 router sites, `runs.py:35-66`, `connections.py:217,368,411`, 3 guard sites) and a 422 list. The web client parses all three (`utils/api/request.ts::toApiError`), so the string sites can migrate without a client change.
- **Route order dependence**: `api/main.py:117-119` must register `domain_buy` before `domains` because `GET /domains/{name}` is a catch-all; `domains.py:253 egress-ip` has the same constraint. A regex-constrained `{name}` or a `/domain-purchases` prefix removes the ordering rule.
- **Process model**: the scheduler starts in lifespan with no `shutdown()` after `yield`, no `misfire_grace_time`/`coalesce` on the digest job (a host asleep at 06:00 skips the day silently), in-memory `FLOWS` (`oauth.py:69`) and dry-run jobs (`collectors.py:225`); `--workers N` would run N schedulers. Safe only because `api/Dockerfile:10` runs one worker; say so in the Dockerfile and README.
- **`claim_assist` documented as atomic** (`job_apply.py:64-68`) but implemented as read-then-write (`:695-697`); a conditional `UPDATE ... WHERE assist_state='queued'` with a rowcount check makes it true.
- **Web**: layering is clean (0 direct `$fetch` in pages, 0 `any`, 0 `ts-ignore`, 0 TODO). Design-system drift is small: three `q-table`s without `dense`, DomainTable status badges colour+text without icons, domain pages' empty state is a bare `div` instead of `EmptyState`. Four files over 450 lines (`ConnectionDialog.vue` 815, `JobsProfilePanel.vue` 798, `pages/collectors.vue` 644, `JobCompaniesPanel.vue` 514) split cleanly along existing testids. `jobs/index.vue` refetches on every filter change and `DomainDetailDialog.load()` has no stale-response guard, while `packages.vue` and `PackageDetailDialog.vue` have one (the 1.3.0 CHANGELOG fix); a shared `useLatestLoad()` closes both.
- **Container hygiene**: no `.dockerignore` (build context includes `venv/`, `web/node_modules/`, `data/`, `tokens/`, `.env`), no `USER`, no `HEALTHCHECK`, `depends_on` without a health condition.

## Recommendation

### Decision

Keep the current architecture (pipeline / api / web, SQLite, APScheduler 3.x) and finish the consolidation in two plans rather than a rewrite: **plan A `repo-cleanup-2`** (mechanical consolidations that touch test doubles: LLM-call helper, settings helpers, oauth finish flows, web test helpers, dialogs/loaders, lint config, docs restructure, dependency bumps) and **plan B `core-split`** (health.py and connections.py split, router orchestration moved into pipeline, one error contract, scheduler process-model guards, Nuxt 4 upgrade). Wire `reconcile_unknown()` first, in plan A, because it is the open P2 defect with a user-visible consequence (an unconfirmed purchase never resolves).

### Rationale

- The review found no P1 code defect left and no layering debt; the remaining cost is repetition, which is cheapest to remove task-by-task with the existing suites as the oracle (3472 + 528 tests, order-independent since the isolation fixture).
- This branch proved the approach: about 560 net lines removed, duplication 1.36% to 0.47%, no behaviour change, no new type errors, all suites green from a clean checkout.
- The two god modules and the router-held orchestration are the only changes that need design decisions (module boundaries, error shape), so they belong in a separate plan with a spec rather than being folded into mechanical work.
- Nuxt 3 is unmaintained since 2026-07-31 while the UI library already targets Nuxt 4; deferring the upgrade only widens the gap.
- A rewrite is not justified: `packages/` already shows the target shape for the feature packages, and the suites make incremental convergence safe.
